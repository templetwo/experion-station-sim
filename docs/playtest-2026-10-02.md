## 1. Summary

### How it was launched
- I read only `README.md`, the run instructions and `Launch Station.command`. I did not read application source.
- The README offers three launch paths. The AI-coach path (`tools/coach/launch.py`, needs Ollama or Anthropic) was not used.
- Instead I used the self-contained offline build `dist/experion-station-sim-standalone.html`:
  - Served it with `python3 -m http.server 8765 --bind 127.0.0.1` from the repo root, left running in the background (log: `server.log`).
  - Drove it with headless Google Chrome 154 (`--remote-debugging-port=9222`, 1280×800) and Python Playwright (venv in `/workspace/experion-playtest/venv`) over CDP.
- It is a browser single-page app. All automation is DOM/mouse/keyboard against the operator UI.
- The PIP coach panel shows "OFFLINE" because no model sidecar was run. This is expected and not tested.

### Overall verdict
**The simulator is usable and impressively deep as a training aid.** These worked correctly and were journaled:
- ISA-18.2 lifecycle (UNACK → ACKED → RTNUN → cleared)
- Shelving with mandatory reason and timed re-annunciation
- State-based and dynamic alarm suppression
- Security levels
- Entry limit checking
- Restart lockout
- Overflow and reactor HI-TEMP trips
- Bumpless MAN↔AUTO (on PV-tracking loops)

However, I confirmed several control-logic and HMI-state defects that would teach operators wrong habits or erode trust:
- Integral windup on the feed-flow loop with a surge on pump restart
- A pending setpoint is written just by clicking the Command zone
- Batch HOLD that doesn't hold
- The event journal is erased and the station clock shifted whenever a drill starts
- Out-of-range PVs shown as good values
- An Experion "trip point" label that doesn't match the real interlock

## 2. Confirmed defects

### D1 — Feed-flow loop FIC102 winds up to 100 % when P-101 stops, then surges far past its SP limit on restart **[P1→P2]** — HIGH
- **Repro:**
  1. U1 in steady state: FIC102 in CAS under LIC101, P-101 running.
  2. Stop P-101: open the P101 faceplate and press STOP, or let drill D3 trip it.
  3. Watch FV-102: within ~25 s it ramps to 100 % while FIC102 PV = 0.
  4. After the 15 s lockout, START P-101.
- **Expected:**
  - The loss of the pump (feedback STOPPED) should force or hold FIC102: IMAN/initialise, or OP to a safe value. At minimum, anti-reset-windup should prevent the integral from saturating against a dead process.
  - On restart, flow should come back at or below SP. SPHILM is 80 m3/h.
- **Observed:**
  - FV-102 goes to 100 %, and so does LIC101's output demand.
  - On restart, flow jumps to **101.7 m3/h** (1st run) and **93.7 m3/h** (2nd run), well above SPHILM 80, then decays over ~1 min.
  - TG02 shows OP pinned at 100 % for the whole outage.
- **Consequence:** A real restart would slug the reactor with ~1.6× design feed. Here it was followed by a reactor temperature excursion. Trainees learn that "just restart the pump" is benign.
- **Reproducibility:** windup 3/3 (operator stop ×2, D3 trip ×1); surge 2/2.
- **Screens:** `screens/p1_038_trend_tg02.png` (OP flat at 100 % then surge), `screens/p1_100_windup_repro2.png`, `screens/p2_017_d3_windup_repro3.png`, `screens/p1_031_almsumm_after_pump_stop.png`
- **Missing feedback:** Live Diagnosis did say "FIC102 output saturated at 100 %", but nothing tells the trainee to put FIC102 in MAN before restart.

### D2 — A typed-but-not-entered faceplate SP is written when the operator clicks into the Command zone **[P1→P2]** — HIGH
- **Repro:**
  1. Open the TIC201 faceplate and click the SP field (SP 150).
  2. Type `157`. Do **not** press Enter.
  3. Click the Command zone (e.g. to type `TREND`).
- **Expected:** An un-entered value is discarded when focus leaves the field. In Experion, a data entry is only stored on Enter.
- **Observed:** The SP is stored at the moment of the click, and the journal shows `TIC201 SP CHANGE 150.00 → 157.00 OPERATOR`.
  - Seen at 20:40:30 (155), 20:48:05 (157) and 20:48:09 (158).
  - Clicking display buttons (TREND, GRAPHIC, ALM SUMM) instead leaves the edit open. The field then persists across display changes, and stray keystrokes later produce misleading "ENTRY REJECTED — SP LIMITS 100.0 TO 170.0" messages for values that look in-range (e.g. a field silently holding `1511`).
- **Consequence:** An unintended setpoint write on a reactor temperature controller, attributed to the operator in the audit trail.
- **Reproducibility:** commit-on-command-zone 3/3. Clean display-button navigation 0/4 commits (but the edit stays open).
- **Screens:** `screens/p2_006_pending_sp_committed_by_command_enter.png`, `screens/p2_004_nav_away_commit_trend.png` (edit field still open over TREND with `1511`), `screens/p1_117_nav_away_commit_repro.png`

### D3 — Batch HOLD does not hold: the phase timer keeps running, the charge continues, and the sequence advances CHARGE → HEATUP **[P1→P2]** — HIGH
- **Repro:**
  1. U2: press START BATCH.
  2. Within a few seconds press HOLD. The banner shows `HELD · CHARGE`.
  3. Watch LI215, the phase timer and JV-213.
- **Expected:** HOLD freezes the sequence: no phase transitions, charge/feed stopped, equipment to the hold state. The journal says "SEQUENCE HELD — FEED STOPPED".
- **Observed:**
  - LI215 keeps rising (14.8 → 40 %).
  - The timer runs (00:05 → 00:43).
  - At charge-complete the SCM logs `PHASE → HEATUP` while still HELD, opens jacket valve JV-213 (0 → 44 %) and switches TIC212 MAN → AUTO. Heating continues (TIC212 15 → 28 °C).
  - The banner reads `HELD · HEATUP` with the timer running.
- **Consequence:** The operator believes the batch is frozen while it heats a charged reactor. On a real semi-batch polymerisation, that is the classic monomer-accumulation / runaway setup.
- **Reproducibility:** 2/2.
- **Screens:** `screens/p1_110_u2_held_heatup.png`, `screens/p2_021_hold_repro.png`, `screens/p2_022_hold_advanced_heatup.png`

### D4 — Starting any drill erases the Event Summary / MOC audit trail and silently "restarts" the station **[P1→P2]** — HIGH
- **Repro:**
  1. Operate for a while: SP and mode changes, alarms, shelving.
  2. Drills ▸ Start Drill… ▸ D4 (or D3) CANONICAL.
  3. Open EVENT.
- **Expected:** The journal is an audit trail and must be append-only. A drill/IC load should add an "INITIAL CONDITION LOADED" record, not remove history.
- **Observed:**
  - All prior records are gone: 97 lines down to 4 in the second run.
  - A new `OPERATOR STATION STARTED — SIMULATION MODE` record appears, and System Status uptime resets.
  - The KPI window and bad-actor history are lost with it.
- **Consequence:** Trainee actions and alarm history before the drill cannot be reviewed. MOC "who changed what" evidence disappears.
- **Reproducibility:** 2/2 (D4 at 20:20:52, D3 at 20:57:07).
- **Screens:** `screens/p1_080_event_after_comment.png` (journal begins at 20:20:35 although the session began 20:04), `screens/p2_016_d3_started_clock.png`

### D5 — Drill start shifts the station clock +2:00 ahead of real time, permanently for the session **[P1→P2]** — MEDIUM
- **Repro:**
  1. Note the status-bar clock: it matches wall time.
  2. Start any CANONICAL drill.
- **Expected:** The station clock stays real time, or sim time is clearly labelled as such.
- **Observed:**
  - Wall 20:57:05 / station 20:57:05 before the drill. Wall 20:57:09 / station **20:59:09** after it.
  - The offset stays constant (+2:00 sampled at +10 s and much later).
  - The first occurrence was +1:43 to +2:00. Example: alarms stamped "20:22:56" appeared at wall 20:21:39.
  - Every alarm and event time thereafter is ahead of real time. The IC record says "SIM TIME 20:59:06".
- **Consequence:** Times reported to a shift log, supervisor or instructor won't match the wall clock. Debrief latencies are internally consistent, but confusing.
- **Reproducibility:** 2/2.
- **Screens:** `screens/p1_062_d4_alarms.png` (alarm times ahead of capture time), `screens/p2_016_d3_started_clock.png`

### D6 — Operator SP entry on FIC211 during a batch is journaled as accepted but silently overwritten by the sequence — MEDIUM
- **Repro:**
  1. U2: START BATCH.
  2. During CHARGE, open the FIC211 faceplate (MODE AUTO · MODEATTR **OPERATOR**).

### D7 — PV displayed far outside its instrument range with no over-range or bad-quality indication **[P1→P2]** — MEDIUM
- **Repro:**
  1. Lose jacket cooling: drill D4, or put TIC202 in MAN with OP 0 (pass 2).

- **Expected:** The transmitter saturates at about 100–105 % of range and the PV shows over-range / uncertain status (crosshatch, which the README mentions exists).

### D8 — Cascade primary in INITMAN does not track its secondary; return to CAS bumps the secondary SP — MEDIUM
- **Repro:**
  1. TIC202 (secondary) CAS → AUTO.
  2. Enter TIC202 SP 75 (or 78).
  3. Open TIC201 (primary). It shows `MODE AUTO … INITMAN`.
  4. Return TIC202 to CAS.
- **Expected:** In INITMAN the primary OP back-calculates to the secondary's SP. The CM view itself says "back-calculation keeps the primary tracking for bumpless return". Return to CAS should then be bumpless.
- **Observed:**
  - TIC201 OP shows **100.0 %** while initialised (2/2).
  - On CAS return, the TIC202 SP stepped **75.0 → 65.7 °C** within 0.3 s, then wandered 59–67 while the primary unwound.
- **Consequence:** A bump on the reactor coolant loop at mode transfer. The displayed OP is misleading.
- **Reproducibility:** OP-at-100 in INITMAN 2/2; SP bump on CAS return 1/1 (not retried because of time).
- **Screens:** `screens/p1_053_tic201_mode_when_secondary_auto.png`, `screens/p1_054_tic202_back_to_cas_bump.png`

### D9 — "Trip point" label on TIC201 PVHH (175 °C) does not match the real R-201 trip (185 °C); the drill scorer then credits "trip avoided" **[P1→P2]** — MEDIUM

**Things that behaved well** (for balance):
- SP/OP limit checks with clear messages: 999, -5, abc, empty, 1e9, 150 % and -10 % were all rejected.
- MAN entry is blocked outside MAN ("INVALID MODE — OP ENTRY REQUIRES MAN"), and a CAS SP is protected.
- Bumpless MAN↔AUTO↔CAS on FIC102.
- Restart lockout (15 s), and rapid START/STOP spam was handled.
- 20 rapid mode toggles were all journaled with no crash.
- Shelving needs a reason and re-annunciates on expiry (`PVHI SHELVE PERIOD EXPIRED — ALARM RE-ANNUNCIATED`).
- RTN-unack retained until acknowledged.
- State-based alarm limits per batch phase are journaled.
- TK-101 HIHI overflow trip and R-201 HI TEMP trip both act, and their consequential alarms are DAS-suppressed with a reason.
- View-only (signed off) blocks ACK and mode changes, and a wrong password is rejected.
- START BATCH during DRAIN is rejected ("SEQUENCE ALREADY RUNNING").
- No JS console errors or page errors were observed.

## 5. Proposed improvements
1. **Windup (D1):**
   - Tie FIC102 to P-101 feedback: on pump stop or trip, force it to IMAN or OP = SAFEOP, and initialise LIC101.
   - Add external-reset or anti-windup in `pid` for any loop whose final element is ineffective.
   - Add a drill step teaching "MAN at low OP before restart".
2. **Entry handling (D2):**
   - Commit a data entry only on Enter. Discard it on blur, Escape, display change or faceplate close.
   - Close any open entry field when the display changes.
3. **Batch HOLD (D3):**
   - HOLD must freeze phase transitions and the phase timer, and drive the phase's hold logic (feed off, jacket to hold).
   - Show HELD distinctly. Make RESUME the only way back.
4. **Journal and clock (D4/D5):**
   - Make the journal append-only. Write an "IC LOADED / DRILL START" marker instead of clearing it.
   - If sim time must differ from wall time, label it ("SIM 20:59:09").
5. **Mode attribute honesty (D6):**
   - When the SCM owns an SP, show MODEATTR PROGRAM and reject operator entries with a message.
   - Never journal an un-applied change.
6. **Instrument range (D7):** Clamp the PV at the transmitter range, flag over-range with the existing crosshatch/uncertain quality on the faceplate and graphic, and raise a BADPV/over-range diagnostic.
7. **Cascade initialisation (D8):** In INITMAN, set primary OP = back-calculated secondary SP, so that both OP and the CAS return are bumpless.
8. **Trip labelling (D9):**
   - Show the actual interlock setpoints (185 °C) on the ladder, and label PVHH "pre-trip".
   - Score "Trip avoided" against the documented trip point, or show the margin to it in the debrief.
9. **Interlock indication (D10):** Show an interlock/override flag on faceplates whose output is forced, and reject or hold OP entries while forced.
10. **HMI quality (D11–D14, U5–U14):**
    - Make the asset label live.
    - Make columns sortable (with an indicator).
    - Clear the Message Zone on the next valid action.
    - Display `0.0` instead of `-0.0`.
    - Focus the comment field automatically.
    - Freeze list order or highlight new rows instead of re-ordering under the cursor.
    - Pen click = select, with SIGNAL PATH via a context action.
    - Add trend cursor, zoom and pan.
    - Larger graphic fonts, or scale-to-fit.
11. **Session robustness (U1/U2):**
