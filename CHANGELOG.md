# Changelog
All notable changes to the simulator. Semantic versioning.

## [3.0.0] - Unreleased
Major version: adds a conceptual architecture-training layer over the unchanged v2 station -- a derived FIELD → IO → CONTROL → NETWORK → SERVICE → HMI → INFORMATION graph teaching a trainee what exists behind a point, a composable instructor-only fault engine, and a twelve-drill (A1 to A12) evidence-scored architecture-diagnosis curriculum, alongside the existing D-series drills (eight exist -- D1, D2, D3, D4, D6, D9, D11, D12; "D1 to D12" is their id range, not a count) and every alarm, model and instructor behaviour from 2.0.0. **v2 behaviour is untouched by design**: a golden-regression suite pins the exact end state, alarm sequence and score of every drill and every legacy upset, and both builds reproduce those digests byte for byte; the five trip thresholds (98 % TK-101, 185 °C R-201, 950 kPa PSV, 110 °C R-202, 480 °C R-310) are unchanged. Two hard rules were added for this major version and hold across the whole diff: no employer or real-site material of any kind, ever, including at a demo/training database (V3-PLAN rule 6); and the deterministic core never waits on a network or a model -- any future AI or network capability is a separate, optional sidecar that only observes and proposes (V3-PLAN rule 7, section 12).

**This entry describes the v3 branch as it stands on disk.** `origin/v3` exists as of 2026-08-31 (Anthony pushed). `main` remains shipped 2.0.0. **Do not cut the 3.0.0 tag.** A clean-sha audit of `cf5693a` (counter-signed `docs/dev/TAG-AUDIT-2026-08-31.md`) found 3 of 7 §2 rows met and 4 partial. S0/SA/S1 are landed. S2/S3 have artifacts. S4's exit condition is not met: A-drill replay does not reproduce score (gate 3 falsified; measured 4 events / 60 before replay, 0 / 0 after). Debrief is not the specified synchronized view. The snapshot is version-marked, not the §4 schema. Coverage ticks and architecture Alarm Help/philosophy were already named as unfinished. The suite (708 / 707 / 1 skip) is green because several tests encode those gaps as passing expectations.

### Added
- **Conceptual architecture view** (`src/topology.js`, `src/signal-path.js`, `src/architecture-view-model.js`, `src/debrief.js`; command `ARCH` or `SIGNAL PATH`): a FIELD → IO → CONTROL → NETWORK → SERVICE → HMI → INFORMATION graph **derived** from the simulator's own tag database (114 nodes, 247 edges, 24 resolvable point paths) rather than hand-authored, so it cannot silently drift from what the simulator actually models. Learn shows layers, terminology and blast radius; Trace follows a selected point or command; Diagnose withholds blast radius and the answer; Debrief is an ARCH mode (TRAINEE_SAFE hides fault ids) but not yet the specified synchronized timeline. SIGNAL PATH entry points on faceplates, Point Detail, the Alarm Summary and trend pens open the view pre-scoped to that tag. Console and flex station profiles resolve genuinely different node sets -- flex reaches the station through a simulated data-server cache leg that console does not depend on -- which is the distinction A8 (server vs controller) teaches. Every architecture surface carries the required banner, "Conceptual training architecture. Simulated; not a Honeywell diagnostic display." Learn is hidden, not disabled, while an A-drill is running. Debrief as an ARCH mode exists; it is not yet the specified synchronized architecture/process/alarm/action/score timeline (no score passed in, active-faults-only topology, process samples stripped at render).
- **Command/event boundary** (`src/dispatch.js`): a canonical `dispatch({type, actor, target, payload, simTime})` that wraps the existing instructor journal -- entries keep their `{t, op, tag, arg}` shape and gain `actor`/`accepted`/`reason`, so the v2 journal display and replay keep working unchanged. Evidence/hypothesis/verify go through it at the live call site. A-drill arm/fire and snapshot restore still bypass it. Replay of `TRAINING.*` journal ops is not wired in `applyJournalEntry` (ADRILL re-arms, the four scoring commands are dropped). `ESS.Sel` is not implemented.
- **Composable fault engine** (`src/fault-engine.js`): thirteen fixed fault transforms -- V3-PLAN's full fault catalogue (section 5), spanning FIELD through INFORMATION -- as instructor-only state transforms, each producing a separate trainee (symptoms-only) and instructor (root-cause) projection from one underlying state. Three of the thirteen (`FROZEN_MEASUREMENT`, `BIASED_MEASUREMENT`, `VALVE_RESPONSE_FAILURE`) re-register the three ARCHITECTURE-class legacy upsets (`xmtr`, `drift`, `stick`); the other ten are new architecture-domain fault types with no legacy-upset counterpart, and the nine PROCESS-class legacy upsets stay outside this catalogue by design (see the upset-class-honesty gate below). Refuses to activate a magnitude-bearing fault without an explicit magnitude or a seeded PRNG; never falls back to `Math.random`. Wired into the running simulator through `setArchFault` / `archFireFault` and the instructor Architecture panel.
- **Architecture drill library** (`src/drill-arch.js`): twelve drills, A1 to A12, defined as data, each citing its own `sourceBasis` provenance rather than sharing one default. An evidence-first scorer reads journaled commands (`TRAINING.MARK_EVIDENCE`, `TRAINING.PIN_COMPARE`, `TRAINING.SUBMIT_HYPOTHESIS`, `TRAINING.VERIFY`) and applies a safety gate that caps a score below pass whenever a drill's own definition marks an action major-unsafe, regardless of points otherwise earned. Composes with, and does not replace, the existing `ESS.Kpi.scoreDrill`; the D-series scorer is byte-for-byte unchanged. Reachable from the trainee Drills menu: START loads the drill's `basePreset`, arms `startADrill`, and opens ARCH in Diagnose. Scoring commands are Diagnose-only at the dispatch layer. Each drill has a live scored fixture under `tests/fixtures/arch/`. The curriculum is not fully completable: `TRAINING.DEBRIEF` is never called from the page; `endADrill` discards the event array; INTERLOCK.DEFEAT (A5/A12) is never synthesized from a real UI action. Clean-run fixtures: A1 can reach 90 with ACK; A2–A12 sit 60–70 because stabilize and debrief are unreachable on engine-only faults.
- **Instructor compound scripts** (`ESS.Instructor.compoundScripts`): ordered fault timelines (V3-PLAN section 8 example: net-path degradation, then a transmitter bias, then history loss). RUN schedules each step through the same `ARCH_FAULT_ACTIVATE` dispatch as a matrix injection.
- **`ESS.MODEL_ID`**: a build-time hash of the app page plus every `src/` module, stamped identically into both builds by `tools/build-dist.py` (the generated `src/model-id.js` -- do not hand-edit, same as `dist/`). Every new fixture and the determinism invariant carry it, so a changed digest now reads as "behaviour changed" or "build changed" instead of being ambiguous.
- **Golden regression baseline** (stage S0): `tests/golden-drills.test.js` and `tests/golden-upsets.test.js` pin the exact end-state digest, alarm sequence, trips/faults and scored outcome of all eight drills that exist in the runtime and all twelve legacy instructor upsets, captured before any v3 code existed. `tests/determinism.test.js` adds a clock-origin-invariance proof (`P.t`'s `Date.now()` seed is a display origin, not a dynamical input -- every model use of it is a difference against a fault timestamp, so the origin cancels) and a guard that fails if a model step is ever taken without a seeded `ctx.rand`.
- **Four verification suites** protecting the rest of the plan as later stages land: `tests/leakage.test.js` (45 cases across all 13 faults and all 12 drills -- no trainee-visible projection may carry a fault id, instance id, `INSTRUCTOR_ONLY` marker, recovery text or root-cause note, proven with positive controls that the detector actually trips); `tests/provenance.test.js` (15 cases -- every `sourceBasis` id resolves to a registered `docs/RESOURCES.md` section); `tests/refusal-scoring.test.js` (10 cases -- the safety gate is outcome-based: a refused unsafe attempt does not trip it, only an accepted one does); `tests/upset-class-honesty.test.js` (the twelve legacy upsets split 3 ARCHITECTURE-class -- `xmtr`, `drift`, `stick` -- to 9 PROCESS-class, including `air`: an instrument-air loss drives a valve to its own designed fail-safe position, which is the architecture working, not failing; one assertion stays skipped until stage S2 wires `ESS.UpsetBridge`).
- **Artifact classification** (`tests/artifact-classes.test.js`, `tools/strip-dev.sh`): every tracked file now declares `@artifact production` or `@artifact dev` in its first three lines, so a release tree can be reduced to what a trainee needs mechanically instead of file by file. `CHANGELOG.md` is `production` and canonical -- this file is never stripped.
- **Developer tooling**: `docs/dev/V3-PLAN.md` (the v3 contract: Anthony's spec plus an architect's addendum recording what was verified against the code before work began) and `CLAUDE.md` (the coding-agent onboarding contract).

### Fixed
Found during v3 integration; none of these are v2 operator-facing behaviour, which the goldens keep frozen.
- `tests/golden-upsets.test.js` asserted the recorded `ESS.MODEL_ID` matched the golden's -- which would have failed all thirteen upset goldens the moment any later stage added a module, for a reason unrelated to behaviour, and would have taught the next reader to re-capture the baseline it exists to protect. `model` is provenance only now.
- The S0 fixture digest (`tests/_fixture.js`) was blind to latched and sequenced state -- trips, fault flags, batch phase/accumulation, fouling, the TI216 interlock latch, the applied state-based alarm-limit set -- so a later stage could have broken any of them with no digest moving. `endState()` now captures all six, so none can drift silently. Its alarm sort also used `localeCompare`, which is host-locale dependent by spec and would have made a digest unreproducible across machines; it is a byte comparison now.
- `src/topology.js`'s node-merge on `build()` **replaced** an existing node instead of merging, so two points sharing one control module silently dropped the first from its `pointRefs` and from `blastRadius()` -- exactly what a trainee uses to reason about what a failure affects -- with `validate()` raising nothing. Latent today (no current tag shares a control module) but fixed before anything depended on the bug.
- Topology edges first encoded dataflow direction (`CM → CEE → CTRL`), which inverted the dependency a fault needs: `blastRadius(CTRL-U1)` reported ten downstream nodes and **zero** affected points. Hosting is now explicit (`CTRL → CEE → CM`).
- Only one historian read-back edge existed, to the console profile; a historian gap now shows on a trend at either profile, which is what the (not-yet-shipped) historian-gap drill needs to be diagnosable from the gap rather than from where the trainee happens to be sitting.
- `src/drill-arch.js` referenced four fault ids `src/fault-engine.js` had never heard of (`BAD_QUALITY_INPUT`, `NETWORK_PATH_DEGRADED`, `SERVER_DEGRADED`, `STATION_LOSS`) -- the vocabulary had been fixed in prose across two work briefs instead of in a file, so nothing could catch the drift until a new cross-module contract suite was added.
- Provenance ids used two spellings for one registry (`RESOURCES 2.14` with a space, `RESOURCES-2.14` with a hyphen) across two modules, and all twelve A-drills shared one default `sourceBasis`, so a frozen field transmitter (A1) and a historian gap (A10) claimed identical provenance -- satisfying release gate 5's letter while failing its intent. Canonicalised to `RESOURCES-<section>` for all data-level citations; every drill now cites its own basis and no two are identical. (An internal spec section is also not a public source; a citation of this repo's own plan document was replaced with a real one.)
- `tests/artifact-classes.test.js`, which defines "the files in the repo" via `git ls-files`, produced five spurious failures on an otherwise-green tree when read from a `git archive` export with no `.git` metadata -- a false negative, the more dangerous failure because it teaches people to ignore the suite. It now skips with an explicit reason instead. `tools/strip-dev.sh` had the same gap (no git guard, so it could silently write an *empty* release tree with `--out`) plus an unrelated bug: it died with an unbound-variable error on macOS's default bash 3.2 when a file-class array was empty. Both fixed.
- `tests/upset-class-honesty.test.js` landed at a stale 4-ARCHITECTURE/8-PROCESS split that classified `air` as architectural, the reverse of the actual ruling -- green only because a 4/8 split still covers all twelve upset keys, so nothing in its own preconditions caught it. Corrected to 3/9, with the classifying principle (is a modelled architecture component itself faulty, or is the architecture intact and something else -- a plant utility, an operator error -- went wrong?) now stated in the file's header rather than left implicit in a list.

### Known limitations
Carried forward from v2, recorded but not yet addressed by any landed v3 stage:
- `c.step(dt)` draws a fixed number of seeded PRNG samples regardless of `dt`, so a trajectory depends on the *number* of step calls, not on simulated time -- a replay that reconstructs elapsed time with a different `dt` will diverge. Debrief replay uses the same step sequence as the live run, so it is not hit when replay is driven from the journal.
- A12's `BIASED_MEASUREMENT` targets `XMTR-TIC201`, which is not one of the three reserved legacy pairs, so the fault is engine-health only and does not drive `src/models.js`. The cascade the drill describes is not a process cascade in this wiring; ACK is unreachable and the R-201 trip abort does not fire. Same honest 60-point ceiling as the other engine-only A-drills.
- Engine-only A-drills (A2, A4-A11, A12) cannot earn the stabilize (ACK) category because they raise no process alarm. The debrief category is scored in Debrief mode after the run, not inside the live Diagnose script.
- A-drill replay does not reproduce retained events or score. `applyJournalEntry` handles `ADRILL` / `ADRILLEND` and drops `TRAINING.*`. Measured on this seat: 4 accepted events / score 60 before replay, 0 / 0 after.
- `restoreSnapshot()`'s event truncation is boundary-inclusive (`e.t <= t`); restoring the same snapshot instant twice in one process accumulates a duplicate bookkeeping event.
- `ESS.Kpi.scoreDrill`'s other-trips row computes `-Math.min(cap, 0)`, a negative zero, when a drill has no other-equipment trips.
- Two `Math.random()` fallbacks and one `Date.now()` fallback remain in `src/models.js` and the app for when `ctx.rand` is absent. The app always seeds, so they are unreached in practice; the new determinism guard (above) exists so a future caller that forgets `ctx.rand` fails loudly instead of silently reaching one.

## [2.0.0] - 2026-08-29
Major version: the alarm lifecycle, the process models and the drill scorer were replaced, alarm records and the debrief result changed shape, and the page now loads nine plain-script modules from `src/` before `support.js`. Behaviour the operator already knew (three units, drills D1 to D12, command zone, F1 to F4, faceplates, Point Detail, trends, security levels, Ops Assistant) is kept; the five trip thresholds (98 % TK-101, 185 °C R-201, 950 kPa PSV, 110 °C R-202, 480 °C R-310) are unchanged.

### Added
- **ISA-18.2 alarm engine** (`src/alarm-engine.js`): every alarm carries a state (NORM, UNACK, ACKED, RTNUN, SHLVD, DSUPR, OOSRV), a sub-priority 0 to 15 (per condition, defaults TRIP 15, PVHH/PVLL 12, PVHI/PVLO 8, DEVHI 6, CMDFAIL 4), first and last time, repeat count, comment, shelve reason and timer, and the trigger that suppresses it. Deadband (1 % of span, `ALMDB`) and on-delay (`ALMDELAY`; flow loops 15 s, level loops 60 s, AI316 10 s, FIC211 30 s) stop chattering. Indication per state: blink only while UNACK, inverse blink in RTNUN, steady when ACKED, grey and silent for shelved, suppressed and out-of-service; the horn sounds for UNACK only. Every alarm journals two events (ALARM on entry with priority and sub-priority, RETURN TO NORMAL on return), and ACK, SHELVE, UNSHELVE, SUPPRESS, OOS and RTS are operator events with from/to states. Sources: ISA-18.2 state model (alerta, 2.5), on/off delay and maximum shelve time (loxalarm, 2.9), Siemens indication table (2.6), Experion LX spec sub-priority and two-events-per-alarm convention (2.1).
- **Shelving with a reason**: standard reasons plus free text, 5/15/30/60 min chips, 60 min cap, auto-unshelve re-annunciates if the condition still stands; the Shelved view shows remaining time and reason. Shelve without a duration or reason is refused (Experion Alarming PIN, 2.2).
- **Dynamic alarm suppression** (`dasRules()`): a fixed map of the follow-on alarms of each trip (P101, TK-101, R-201, R-202, M202, R-310); suppressed alarms are listed under the SUPPRESSED view with their trigger.
- **Out of service** from Point Detail > Alarms (ENGR and above, signed): a condition that has never alarmed can be taken out of service; OOSRV never annunciates; status bar shows `OOS n`.
- **Alarm Summary parity** (Experion Alarming PIN feature list, 2.2; our own layout and prose): location/asset pane (PLANT, U1 to U3, equipment) with live active/unacknowledged counts and one-click filtering; Trip and Live value columns (live value read from the point PV, PV minus SP for DEVHI, or the model variable an equipment trip protects); State and sub-priority columns; repeat folding inside 10 min with a count column; per-alarm COMMENT dialog (OPER and above, journaled); MAIN/UNACK/SHELVED/SUPPRESSED/OOS views plus built-in per-unit views and SAVE VIEW; ACK PAGE acts on the visible rows only; Alarm Tracker strip (raises per minute per unit over the last 30 min, click a cluster to filter).
- **Alarm Help** (`src/alarm-help.js`): our own rationalisation entry for every alarm condition of every point plus motor trips, CMDFAIL, BADPV and the equipment trips, with the six fields Priority, Setting, Response time, Consequence, Probable cause, Corrective action (PAS/Hollifield white papers, 2.10). Priority and setting are derived from the live point configuration so the help cannot disagree with the trip point. Shown as a pane in the Alarm Summary and in Point Detail > Alarms; command `ALMHELP`.
- **KPI display** (`src/kpi.js`; command `KPI`): alarms per 10 min (average, peak), floods and per cent time in flood, chattering keys, standing alarms, top-10 bad actors with share, priority distribution against 80/15/5, health verdict; the footer states the thresholds and their sources (exida ISA-18.2 paper, 2.7; alarm-performance-analyser benchmarks, 2.8).
- **Colour philosophy** (`src/palette.js`): every priority colour the station draws comes from one getter; the representative defaults stay the default look, and an ISA-101 preset with the Rockwell process HMI style guide values (2.4) is selectable from the Station menu, the philosophy page and a new `palette` data-prop. Both presets pass a 3:1 contrast audit. Chrome and equipment stay grey per the ASM Consortium gray-background paper (2.11).
- **Limit ladder**: Range / Critical / Standard / Target rungs per PID and indication point (range = span, critical = PVLL/PVHH, standard = PVLO/PVHI, target = engineer band or SP plus or minus 5 % of range; indication points carry a configured normal band), always ordered by clamping. Drawn as a band with a live PV marker beside every overview point box, behind faceplate PV bars, and as a LIMIT LADDER block on Point Detail > Main where ENGR edits `TGTHI` / `TGTLO`.
- **Help > Alarm and display philosophy** (`src/philosophy.js`; command `PHILOSOPHY`): our own prose on grey backgrounds, priority meaning and the 5/10/85 versus 80/15/5 splits, ISA-18.2 states and blinking, shelving versus suppression versus out of service, deadband and on-delay, and the ladder. Sources cited by name: ISA-18.2, EEMUA 191, ASM Consortium, Rockwell process HMI style guide (2.4, 2.10, 2.11, 2.19).
- **Loop Tune tab**: K / T1 / T2 with units and action, ISA-form Kc / Ti / Td and parallel gains, an ENGR PV-tracking toggle, and a step-response sparkline from the loop history.
- **Process models** (`src/models.js`, RESOURCES 4), replacing the inline equations:
  - U1: Henson/Seborg exothermic CSTR (feed concentration fixed, throughput acts through residence time), jacket energy balance after Kantor CBE30338, LearnChemE flash drum; new AI205 reactor conversion indication.
  - U2: Lucia/Finkler/Engell semi-batch polymerisation with an adiabatic end temperature TI216 (High 100, Urgent 106). The Urgent alarm is a level-held interlock: FIC211 to MAN with MV-211 closed and SCM202 held while the condition stands, operator writes to FIC211 refused with a callout, a SYSTEM event on release; the sequence returns FIC211 to AUTO on RESUME so a shed batch recovers without ABORT.
  - U3: Badgwell two-pass fired heater with tube-skin temperatures TI314/TI315 (High 440/450, Urgent 490/500; the Urgent raises `H-310 TUBE SKIN TRIP`, shuts the fuel like the bed trip, resets below 400 °C) and AI316 flue-gas excess O2 (Low 1.5 %, 10 s delay); LearnChemE PFR parametric sensitivity for the fixed-bed hot spot, bounded so every catalyst-activity setting trips, peaks and resets.
  - All new points are on the graphics, Point Detail, history, TG04/TG05, the Ops Assistant and Alarm Help.
- **PID module** (`src/pid.js`): anti-reset-windup with integral back-calculation (Kantor CBE30338, RESOURCES 4), bumpless MAN/AUTO/CAS transfer (integrator re-initialised so the first automatic output equals the current OP), cascade INITMAN, PV tracking (SP follows PV in MAN; on by default for the cascade secondaries FIC102, TIC202, TIC213) and PROGRAM mode-attribute write gating. No loop was retuned; K/T1/T2 are unchanged.
- **PROGRAM mode attribute enforced**: while SCM202 owns a loop, operator SP/OP/MODE stores are rejected with a red callout on the faceplate and Point Detail, a message-zone notice and an OPERATOR journal entry; engineering parameters stay writable; the attribute returns to OPERATOR when the sequence ends.
- **State-based alarm limits per SCM202 phase** (ISA-TR18.2.6 pattern and the InTech state-based limit table, 2.19; ISA-88 phases): a per-phase set for TIC212, TIC213, LI215, FIC211 and TI216 over IDLE, CHARGE, HEATUP, FEED, HELD, REACT, COOL and DRAIN. Level low is disabled in CHARGE/DRAIN/IDLE, monomer flow low is active only in FEED, temperature limits tighten in REACT. Each phase change journals the applied set; Point Detail > Alarms shows `Phase set: <KEY>` and disabled conditions as DISABLED rows.
- **Instructor station** (`src/instructor.js`; command `INSTR`, Drills menu, status-bar SIM link; password `instr` or the MNGR level; OPER/SUPV are sent to the logon dialog): run control (FREEZE, STEP one 0.5 s tick, RUN, 2/5/10x, seed); eight named snapshot slots holding the full process state, alarm records, interlock flags, drill and generator cursor; five initial conditions defined as data; automatic backtrack ring every 30 sim-seconds over the last 10 sim-minutes with -30 s / -2 min / -10 min; twelve upsets (the existing faults plus a LIC101 transmitter drift) with a hidden switch and magnitude sliders; six instructor variables (feed concentration, cooling water supply, ambient, fouling rate, catalyst activity, monomer purity) read by the models; an action journal of every accepted operator and instructor action with REPLAY from a snapshot; live drill assessment; an instructor log. Every random draw goes through a seeded generator, so restore and replay reproduce the same trajectory. In hidden mode the trainee displays carry no trace and the Ops Assistant diagnoses stuck valves and air loss from valve response symptoms. Sources: Forge PTS PIN instructor feature list (2.14); cstr-ots architecture notes on seeded determinism, journal replay and snapshot/backtrack (RESOURCES 4).
- **Standards-based scorer** (`ESS.Kpi.scoreDrill`): acknowledge latency, correct action and its latency, trip avoided, stabilisation, alarm load during the drill (KPI metrics over the alarm log) and the debrief question, weights 20/25/20/15/10/10, breakdown shown in the debrief. The 80 % mark is labelled as an independent training threshold, not a vendor certification (2.7, 2.8, 2.12).
- **Operator name and training record**: the logon dialog captures a free-text operator name beside the level password; the name goes on every journal entry (Event Summary gains an Operator column); the last 20 drill results per name are kept in a Training record dialog (command `RECORD`).
- **Coverage matrix** (`src/training.js`; command `COVERAGE`): our own operator task inventory (42 tasks in eight groups, no vendor task names) mapped to the drills and features that exercise each task, ticking the tasks the session has performed.
- **Message Summary confirm**: instructor prompts, SCM202 charge-complete and batch-complete prompts and the TI216 interlock notice require CONFIRM; unconfirmed messages count in the status bar with a blinking MSG indicator; the confirm is journaled with the operator name (2.12).
- **Electronic signature**: one reusable flow (`withSignature` / `signAction`) gates alarm out-of-service, trip-point and priority changes, PID tuning at ENGR, disabling alarms for an asset and snapshot restore during a drill; the signature (name, level, reason) and every refusal are journaled.
- **Disable alarms for an asset** (MNGR, signed) from the Alarm Summary location pane button or right-click: every condition on the asset goes to DISABLED (OOSRV), new alarms on it are parked without horn or journal line, the status bar shows `ALARMS DISABLED: n`, System Status lists the asset; re-enable annunciates anything still active. ### Known limitations
- Drill D4: cutting reactor feed and leaving it cut fills TK-101 within about 9 minutes; the guidance now says to restore feed, and the tank trip is scored as a secondary deduction rather than the drill's trip.
- Sub-priority is a per-condition default (by condition kind); it is not editable from the station.
- The DAS map is a fixed six-trigger table. M202 TRIP suppresses TIC213 PVHI only; FIC211 PVLO is not listed as a follow-on because it is phase-managed (active only in FEED).
- KPI windows (10/30/60 min) are measured on real elapsed time, so a session younger than the window reports over a shorter span (the window text says when the session started); the standing-alarm threshold is 10 min at the training scale, not the EEMUA field value.
- Loops with a derivative term (TIC201, TIC301, TIC311, TIC212) jitter several per cent per step on measurement noise in every mode; judge bumpless transfer on a P+I loop.
- The tube-skin trip re-opens FV311 when it resets, so TIC311 left in MAN at a high output cycles the trip (same behaviour as the bed trip).
- Initial conditions run the process forward synchronously (the batch presets take up to about 5000 steps), so the page pauses briefly while a preset loads.
- `endDrill` does not clear the `drift` upset, the TI216 shed latch or the skin trip (they are not drill faults); RESET PROCESS or a preset clears them.
- A snapshot restore truncates the journal to the snapshot time, so the E-SIGNATURE event of a signed restore is dropped; the CONFIG entry written afterwards carries the name and reason.
- The message list can exceed 400 entries by the number of pending CONFIRM messages.
- ENGR trip-point edits on the phase-managed U2 points last only until the next phase change.
- In hidden mode the DRILL IN PROGRESS banner remains visible (it names no fault); only the drill-armed and drill-ended messages are withheld.
- The coverage matrix is built from our own 42-task inventory, not from vendor course or video titles; the 80 % pass mark is this simulator's own threshold and is independent of any vendor certification.
- Alarm Help, the philosophy page and all rationalisation fields are our own prose and describe this simulator only; they are not site alarm documentation.
- The standalone reuses the React runtime blobs already in `dist/`; `tools/build-dist.py` requires an existing dist to rebuild from.
