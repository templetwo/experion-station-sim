# Changelog
All notable changes to the simulator. Semantic versioning.

## [2.0.0] - 2026-08-29
Major version: the alarm lifecycle, the process models and the drill scorer were replaced, alarm records and the debrief result changed shape, and the page now loads nine plain-script modules from `src/` before `support.js`. Behaviour the operator already knew (three units, drills D1 to D12, command zone, F1 to F4, faceplates, Point Detail, trends, security levels, Ops Assistant) is kept; the five trip thresholds (98 % TK-101, 185 °C R-201, 950 kPa PSV, 110 °C R-202, 480 °C R-310) are unchanged.

### Added
- **ISA-18.2 alarm engine** (`src/alarm-engine.js`): every alarm carries a state (NORM, UNACK, ACKED, RTNUN, SHLVD, DSUPR, OOSRV), a sub-priority 0 to 15 (per condition, defaults TRIP 15, PVHH/PVLL 12, PVHI/PVLO 8, DEVHI 6, CMDFAIL 4), first and last time, repeat count, comment, shelve reason and timer, and the trigger that suppresses it. Deadband (1 % of span, `ALMDB`) and on-delay (`ALMDELAY`; flow loops 15 s, level loops 60 s, AI316 10 s, FIC211 30 s) stop chattering. Indication per state: blink only while UNACK, inverse blink in RTNUN, steady when ACKED, grey and silent for shelved, suppressed and out-of-service; the horn sounds for UNACK only. Every alarm journals two events (ALARM on entry with priority and sub-priority, RETURN TO NORMAL on return), and ACK, SHELVE, UNSHELVE, SUPPRESS, OOS and RTS are operator events with from/to states. Sources: ISA-18.2 state model (alerta, 2.5), on/off delay and maximum shelve time (loxalarm, 2.9), Siemens indication table (2.6), Experion LX spec sub-priority and two-events-per-alarm convention (2.1).
- **Shelving with a reason**: standard reasons plus free text, 5/15/30/60 min chips, 60 min cap, auto-unshelve re-annunciates if the condition still stands; the Shelved view shows remaining time and reason. Shelve without a duration or reason is refused (Experion Alarming PIN, 2.2).
- **Dynamic alarm suppression** (`dasRules()`): a fixed map of the follow-on alarms of each trip (P101, TK-101, R-201, R-202, M202, R-310); suppressed alarms are listed under the SUPPRESSED view with their trigger.
- **Out of service** from Point Detail > Alarms (ENGR and above, signed): a condition that has never alarmed can be taken out of service; OOSRV never annunciates; status bar shows `OOS n`.
- **Alarm Summary parity** (Experion Alarming PIN feature list, 2.2; our own layout and prose): location/asset pane (PLANT, U1 to U3, equipment) with live active/unacknowledged counts and one-click filtering; Trip and Live value columns (live value read from the point PV, PV minus SP for DEVHI, or the model variable an equipment trip protects); State and sub-priority columns; repeat folding inside 10 min with a count column; per-alarm COMMENT dialog (OPER and above, journaled); MAIN/UNACK/SHELVED/SUPPRESSED/OOS views plus built-in per-unit views and SAVE VIEW; ACK PAGE acts on the visible rows only; Alarm Tracker strip (raises per minute per unit over the last 30 min, click a cluster to filter).
- **Alarm Help** (`src/alarm-help.js`): our own rationalisation entry for every alarm condition of every point plus motor trips, CMDFAIL, BADPV and the equipment trips, with the six fields Priority, Setting, Response time, Consequence, Probable cause, Corrective action (PAS/Hollifield white papers, 2.10). Priority and setting are derived from the live point configuration so the help cannot disagree with the trip point. Shown as a pane in the Alarm Summary and in Point Detail > Alarms; command `ALMHELP`.
- **KPI display** (`src/kpi.js`; command `KPI`): alarms per 10 min (average, peak), floods and per cent time in flood, chattering keys, standing alarms, top-10 bad actors with share, priority distribution against 80/15/5, health verdict; the footer states the thresholds and their sources (exida ISA-18.2 paper, 2.7; alarm-performance-analyser benchmarks, 2.8).
- **Colour philosophy** (`src/palette.js`): every priority colour the station draws comes from one getter; the representative defaults stay the default look, and an ISA-101 preset with the Rockwell process HMI style guide values (2.4) is selectable from the Station menu, the philosophy page and a new `palette` data-prop. Both presets pass a 3:1 contrast audit. Chrome and equipment stay grey per the ASM Consortium gray-background paper (2.11).
- **Limit ladder**: Range / Critical / Standard / Target rungs per PID and indication point (range = span, critical = PVLL/PVHH, standard = PVLO/PVHI, target = engineer band or SP plus or minus 5 % of range; indication points carry a configured normal band), always ordered by clamping. Drawn as a band with a live PV marker beside every overview point box, behind faceplate PV bars, and as a LIMIT LADDER block on Point Detail > Main where ENGR edits `TGTHI` / `TGTLO`.
- **Help > Alarm and display philosophy** (`src/philosophy.js`; command `PHILOSOPHY`): our own prose on grey backgrounds, priority meaning and the 5/10/85 versus 80/15/5 splits, ISA-18.2 states and blinking, shelving versus suppression versus out of service, deadband and on-delay, and the ladder. Sources cited by name: ISA-18.2, EEMUA 191, ASM Consortium, Rockwell process HMI style guide (2.4, 2.10, 2.11, 2.19).
- **Loop Tune tab**: K / T1 / T2 with units and action, ISA-form Kc / Ti / Td and parallel gains, an ENGR PV-tracking toggle, and a step-response sparkline from the loop history.
- **Process models** (`src/models.js`, RESOURCES 4), replacing the inline equations:
  - U1: Henson/Seborg exothermic CSTR (feed concentration fixed, throughput acts through residence time), jacket energy balance after Kantor CBE30338, LearnChemE flash drum; new AI205 reactor conversion indication.
  - U2: Lucia/Finkler/Engell semi-batch polymerisation with an adiabatic end temperature TI216 (High 100, Urgent 106). The Urgent alarm is a level-held interlock: FIC211 to MAN with MV-211 closed and SCM202 held while the condition stands, operator writes to FIC211 refused with a callout, a SYSTEM event on release; the sequence returns FIC211 to AUTO on RESUME so a shed batch recovers without ABORT.
  - U3: Badgwell two-pass fired heater with tube-skin temperatures TI314/TI315 (High 440/450, Urgent 490/500; the Urgent raises `H-310 TUBE SKIN TRIP`, shuts the fuel like the bed trip, resets below 400 °C) and AI316 flue-gas excess O2 (Low 1.5 %, 10 s delay); LearnChemE PFR parametric sensitivity for the fixed-bed hot spot, bounded so every catalyst-activity setting trips, peaks and resets.
  - All new points are on the graphics, Point Detail, history, TG04/TG05, the Ops Assistant and Alarm Help.
- **PID module** (`src/pid.js`): anti-reset-windup with integral back-calculation (Kantor CBE30338, RESOURCES 4), bumpless MAN/AUTO/CAS transfer (integrator re-initialised so the first automatic output equals the current OP), cascade INITMAN, PV tracking (SP follows PV in MAN; on by default for the cascade secondaries FIC102, TIC202, TIC213) and PROGRAM mode-attribute write gating. No loop was retuned; K/T1/T2 are unchanged.
- **PROGRAM mode attribute enforced**: while SCM202 owns a loop, operator SP/OP/MODE stores are rejected with a red callout on the faceplate and Point Detail, a message-zone notice and an OPERATOR journal entry; engineering parameters stay writable; the attribute returns to OPERATOR when the sequence ends.
- **State-based alarm limits per SCM202 phase** (ISA-TR18.2.6 pattern and the InTech state-based limit table, 2.19; ISA-88 phases): a per-phase set for TIC212, TIC213, LI215, FIC211 and TI216 over IDLE, CHARGE, HEATUP, FEED, HELD, REACT, COOL and DRAIN. Level low is disabled in CHARGE/DRAIN/IDLE, monomer flow low is active only in FEED, temperature limits tighten in REACT. Each phase change journals the applied set; Point Detail > Alarms shows `Phase set: <KEY>` and disabled conditions as DISABLED rows.
- **Instructor station** (`src/instructor.js`; command `INSTR`, Drills menu, status-bar SIM link; password `instr` or the MNGR level; OPER/SUPV are sent to the logon dialog): run control (FREEZE, STEP one 0.5 s tick, RUN, 2/5/10x, seed); eight named snapshot slots holding the full process state, alarm records, interlock flags, drill and generator cursor; five initial conditions defined as data; automatic backtrack ring every 30 sim-seconds over the last 10 sim-minutes with -30 s / -2 min / -10 min; twelve upsets (the existing faults plus a LIC101 transmitter drift) with a hidden switch and magnitude sliders; six instructor variables (feed concentration, cooling water supply, ambient, fouling rate, catalyst activity, monomer purity) read by the models; an action journal of every accepted operator and instructor action with REPLAY from a snapshot; live drill assessment; an instructor log. Every random draw goes through a seeded generator, so restore and replay reproduce the same trajectory. In hidden mode the trainee displays carry no trace and the Ops Assistant diagnoses stuck valves and air loss from valve response symptoms. Sources: Forge PTS PIN instructor feature list (2.14); cstr-ots architecture notes on seeded determinism, journal replay and snapshot/backtrack (RESOURCES 4).
- **Standards-based scorer** (`ESS.Kpi.scoreDrill`): acknowledge latency, correct action and its latency, trip avoided, stabilisation, alarm load during the drill (KPI metrics over the alarm log) and the debrief question, weights 20/25/20/15/10/10, breakdown shown in the debrief. The 80 % mark is labelled as an independent training threshold, not a vendor certification (2.7, 2.8, 2.12).
- **Operator name and training record**: the logon dialog captures a free-text operator name beside the level password; the name goes on every journal entry (Event Summary gains an Operator column); the last 20 drill results per name are kept in a Training record dialog (command `RECORD`).
- **Coverage matrix** (`src/training.js`; command `COVERAGE`): our own operator task inventory (42 tasks in eight groups, no vendor task names) mapped to the drills and features that exercise each task, ticking the tasks the session has performed.
- **Message Summary confirm**: instructor prompts, SCM202 charge-complete and batch-complete prompts and the TI216 interlock notice require CONFIRM; unconfirmed messages count in the status bar with a blinking MSG indicator; the confirm is journaled with the operator name (2.12).
- **Electronic signature**: one reusable flow (`withSignature` / `signAction`) gates alarm out-of-service, trip-point and priority changes, PID tuning at ENGR, disabling alarms for an asset and snapshot restore during a drill; the signature (name, level, reason) and every refusal are journaled.
- **Disable alarms for an asset** (MNGR, signed) from the Alarm Summary location pane button or right-click: every condition on the asset goes to DISABLED (OOSRV), new alarms on it are parked without horn or journal line, the status bar shows `ALARMS DISABLED: n`, System Status lists the asset; re-enable annunciates anything still active. The set travels with instructor snapshots.
- **MOC audit**: every configuration change (tuning, SP/OP limits, target band, trip points, priorities, control action, deadband, on-delay, phase sets, palette, PV tracking, OOS/RTS, asset disable) is a CONFIG event with old/new values, operator name, level and reason; command `MOC` opens the change log (Event Summary CONFIG filter); System Status counts changes since startup. Sequence-driven phase sets are attributed to SCM202 at level PROGRAM and excluded from the count (2.13).
- **Developer tooling and tests**: `tools/logic-harness.js` (evaluates the `src/` modules and the Component class under node), `tools/build-dist.py` (rebuilds the standalone), `tools/smoke.sh` (headless Chrome, folder build online and dist build with DNS blocked), `docs/dev/CODE-MAP.md` and `docs/dev/UPGRADE-PLAN.md`; `tests/` with 186 cases across module-level (alarm engine, PID, KPI, palette, models) and app-level (alarms, alarm summary, palette and limits, models, instructor, scorer/MOC) suites.

### Changed
- Alarm record shape (see engine above); `this.alarms` is now a read-only getter over the engine. Priority counters and the Alarm Summary ACTIVE footer count UNACK+ACKED only; the status bar `UNACK n` counts UNACK+RTNUN.
- Alarm Summary is three panes; the Value column is replaced by Trip and Live; State, Cnt and comment columns added; the alarm line shows priority, sub-priority and state.
- Debrief result is PASS / NOT PASSED at 80 with a breakdown; the 85/65 PROFICIENT / COMPETENT / NEEDS PRACTICE grades are gone. `scoreDrill` returns an object.
- The hidden instructor dialog became the INSTRUCTOR display; speed chips are 1/2/5/10 (FREEZE shows FROZEN); RESET PROCESS moved into the presets.
- Logon accepts `instr` (instructor authority only, security level unchanged); the logon dialog has an Operator field; sign-off is journaled.
- `FIC102.SPHILM` is 80 (was 110), the reactor feed limit, so the LIC101 cascade cannot run R-201 into its trip while emptying the tank; a +50 m3/h surge now peaks TK-101 near 86 % and R-201 near 174 °C with High alarms only.
- The `vap` fault multiplier is 2.6 (was 1.9) so drill D9 annunciates with PIC401 left in MAN; in AUTO the vent still holds the drum below 750 kPa. D9 sets up its premise (PIC401 in MAN) through a per-drill setup hook and journals it.
- The `stick` fault carries its own heat step (1.15 on heat only) instead of the full `rxn` fault, so TIC202 to MAN alone stabilises drill D6.
- Fouling: a slow baseline (2 %/h at instructor variable x1, floor 0.6) that the `foul` upset accelerates and recovers to.
- Gated drills (D11) count their 12-minute limit from injection and give up after 60 min if the injection condition is never reached.
- Messages are records with confirm fields, cap 400 non-pending; phase-set, palette and PV-tracking events are type CONFIG (were SYSTEM or OPERATOR).
- Ops Assistant: stuck-valve and air-loss rules are symptom-based; new rules and topics for the TI216 shed, tube skin, excess O2, PROGRAM write rejections, PV tracking and state-based limits; the M202-trip advice points to SCM202 HOLD on the U2 graphic.
- System Status reports 24 CMs, a SIMULATION ENGINE state and an ALARM SYSTEM panel (disabled assets, OOS count, config changes, drill results kept).
- Standalone build: the manifest now inlines the nine `src/` modules beside `support.js`.

### Fixed
- Chattering alarms on noisy measurements (deadband and on-delay in the engine).
- Returned-but-unacknowledged alarms inflated the priority counters and ACTIVE footer.
- Shelve silently defaulted to 15 min when no duration was chosen; it is now refused with a message.
- `endDrill` cleared a fixed fault list, so the `stick` load (and `foul` / `air`) survived a drill; it now clears every drill fault and its timer.
- PROGRAM write-rejection callouts never cleared while the simulator was frozen; they now expire after ten UI ticks as well as on sim time.
- The R-310 hot spot could run to non-finite values at slider extremes; the release now saturates at the adiabatic rise with a preheat light-off, and a snapshot refuses non-finite state instead of storing null.
- An `ALMDB` / `ALMDELAY` store wiped the limit memos and produced a spurious RTN / re-raise pair with horn; only the timers reset now.
- A CONFIRM-required message could be dropped by the message cap.
- A second signature request while one was pending silently replaced it; it is refused with a message, and cancelling a signature restores the dialog it interrupted.
- Instructor journal: actions taken while frozen at the snapshot time were dropped on replay and entries journaled before the save could replay twice (sequence stamps); instructor upsets, magnitudes, variables, seed and drill arming after a snapshot are now replayed; hidden mode scrubs INSTR events already mirrored into the station journal; the security bypass applies only while a replayed entry is being applied.
- The instructor logon accepted any level password and changed the security level; it now accepts only `instr` / `mngr` and leaves the level alone. Random drill draws from the seeded generator.
- A raise on a disabled asset with no prior record reached the horn and journal before being parked; the disabled-asset set was missing from snapshots.
- U3 graphic: the tube-skin trip now shows flames off and its own banner; the AI316 leader is routed to the stack instead of a stub.
- The 12-minute drill limit ended D11 before its alarm when armed from IDLE.
- `parseCmd` ticked the command-zone coverage task for unrecognised commands.
- Drill D4 could not be passed by its own recommended action: the tank high-level trip counted against a trainee who had correctly cut reactor feed. 'Trip avoided' now scores the trips on the drill's own equipment (each drill lists them), other trips during a drill still cost points, and the D4 quiz, debrief and Ops Assistant guidance state the full sequence (cut feed, then restore feed before TK-101 reaches high level). The cooling-loss upset was recalibrated so the drill is winnable: a backup cooling pump restores full jacket duty after 3 min (was 75 % after 5 min), documented in `PARAMS.U1` and the instructor upset label.
- Instructor backtrack '-30 S' landed 30 to 60 s back; it now picks the ring entry nearest the requested age.
- The alarm colour philosophy switch had no security gate; it now needs SUPV and is still recorded as a CONFIG change.

### Upgrade notes
The page head now loads, in this order and before `./support.js`: `src/alarm-engine.js`, `src/pid.js`, `src/kpi.js`, `src/palette.js`, `src/models.js`, `src/alarm-help.js`, `src/philosophy.js`, `src/instructor.js`, `src/training.js`. Each is a UMD plain script (browser global `ESS.*`, node `require`), pure logic, no DOM, no timers, no network; the folder build needs `src/` beside the app and `support.js` (unchanged apart from the 1.1.1 tspan patch). Rebuild the standalone with `python3 tools/build-dist.py` (inlines every `./src/*.js` the page references as a gzip+base64 manifest entry; never hand-edit `dist/`). Run the tests with `node --test tests/*.test.js` from the repo root (the bare `tests/` directory form is rejected by newer node 22 builds); `tools/logic-harness.js` evaluates the modules in document order and then the Component class so app-level tests see `ESS.*` exactly as the browser does. Check both builds in headless Chrome with `tools/smoke.sh`. New data-prop `palette` (`representative` | `isa101`) beside `highColor`. New training password `instr`. Nothing is persisted: snapshots, training records, task coverage and the MOC count live in the page session only (`localStorage` is not used).

### Known limitations
- Drill D4: cutting reactor feed and leaving it cut fills TK-101 within about 9 minutes; the guidance now says to restore feed, and the tank trip is scored as a secondary deduction rather than the drill's trip.
- Sub-priority is a per-condition default (by condition kind); it is not editable from the station.
- The DAS map is a fixed six-trigger table. M202 TRIP suppresses TIC213 PVHI only; FIC211 PVLO is not listed as a follow-on because it is phase-managed (active only in FEED).
- KPI windows (10/30/60 min) are measured on real elapsed time, so a session younger than the window reports over a shorter span (the window text says when the session started); the standing-alarm threshold is 10 min at the training scale, not the EEMUA field value.
- Loops with a derivative term (TIC201, TIC301, TIC311, TIC212) jitter several per cent per step on measurement noise in every mode; judge bumpless transfer on a P+I loop.
- The tube-skin trip re-opens FV311 when it resets, so TIC311 left in MAN at a high output cycles the trip (same behaviour as the bed trip).
- Initial conditions run the process forward synchronously (the batch presets take up to about 5000 steps), so the page pauses briefly while a preset loads.
- `endDrill` does not clear the `drift` upset, the TI216 shed latch or the skin trip (they are not drill faults); RESET PROCESS or a preset clears them.
- A snapshot restore truncates the journal to the snapshot time, so the E-SIGNATURE event of a signed restore is dropped; the CONFIG entry written afterwards carries the name and reason.
- The message list can exceed 400 entries by the number of pending CONFIRM messages.
- ENGR trip-point edits on the phase-managed U2 points last only until the next phase change.
- In hidden mode the DRILL IN PROGRESS banner remains visible (it names no fault); only the drill-armed and drill-ended messages are withheld.
- The coverage matrix is built from our own 42-task inventory, not from vendor course or video titles; the 80 % pass mark is this simulator's own threshold and is independent of any vendor certification.
- Alarm Help, the philosophy page and all rationalisation fields are our own prose and describe this simulator only; they are not site alarm documentation.
- The standalone reuses the React runtime blobs already in `dist/`; `tools/build-dist.py` requires an existing dist to rebuild from.

## [1.1.1] — 2026-08-29
### Fixed
- Process-graphic value boxes (tag / PV / EU / mode / alarm tick) and valve position labels rendered as empty rectangles on all three units: the page runtime (`support.js`) emitted an HTML `<span>` for every `{{ }}` interpolation, and browsers do not paint HTML elements inside SVG `<text>`. The runtime now emits `<tspan>` when the interpolation's parent is an SVG `text` / `tspan` / `textPath`. The same patched runtime is re-embedded in `dist/` (gzip+base64 manifest entry `cb5343e5…`). Verified in headless Chrome, online (folder build) and with DNS blocked (dist build).
